An app to control Viessmann devices. Control it with flows in Homey, check its status, and more.
Get it set up:
* Log in to Viessmann dev portal https://app.developer.viessmann-climatesolutions.com/ with your existing ViCare app user.
* At the Viessmann dev portal add a new client to get a Viessmann Client ID. Name it Homey, ensure Google reCaptcha is turned off and set redirect URI to https://callback.athom.com/oauth2/callback. Viessmann allows only one client per account: if you already have one (for example for Home Assistant or ioBroker), use it and add this redirect URI to it.
* After installation of the Viessmann ViCare Homey app go to settings of the app and enter the ‘Client ID’ generated in the step above.
* Now add your new Viessmann device in Homey and log in with your ViCare app user when asked to.


Heating circuits: the app uses heating circuit 0, or the first enabled circuit when the installation has no circuit 0. You can choose another circuit in the device's advanced settings. One Homey device controls one heating circuit.

## Development

Contributions are welcome. Please read [CONTRIBUTING.md](CONTRIBUTING.md) for the ground rules; [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) explains how the app works.

Requirements: Node.js 22 and the Homey CLI (`npm install --global homey`).

| Command | What it does |
| --- | --- |
| `npm ci --ignore-scripts` | Install dependencies. Nothing is built or deployed. |
| `npm test` | Run the Jest tests against the anonymized fixtures in `test/fixtures/` (plus local dumps in `documentation/json-example-files/`, if present). |
| `npm run lint` | Run ESLint. |
| `npm run generate` | Regenerate `drivers/vicare/driver.flow.compose.json` from `drivers/vicare/flowCards.js` and `locales/`. |
| `npm run homey:validate` | `npm run generate`, then `homey app validate --level publish`. |
| `npm run homey:run` | `npm run generate`, then run the app on your Homey (`homey app run`). Extra arguments go to the Homey CLI, e.g. `npm run homey:run -- --remote`. |
| `npm run homey:install` | `npm run generate`, then install the app on your Homey (`homey app install`). |
| `npm run homey:publish` | `npm run generate`, then publish the app (`homey app publish`). |
| `npm run fixtures` | Regenerate `test/fixtures/` from the raw dumps in `documentation/json-example-files/` (maintainer only). |

`.homeyignore` keeps development files (`documentation/`, `test/`, `scripts/`, `__mocks__/`, `__tests__/`, `*.md`, ...) out of the app package. `app.json` is generated by the Homey CLI from `.homeycompose/` and `drivers/vicare/driver*.compose.json`, and is committed. `drivers/vicare/driver.compose.json` is edited by hand.

`documentation/` holds raw API dumps from real installations (serial numbers, installation ids) and is never committed. To add test coverage for a new installation type, anonymize the dump into `test/fixtures/` (see [test/fixtures/README.md](test/fixtures/README.md)); `test/fixtures.privacy.test.js` fails if anything identifying is left.

CI (`.github/workflows/ci.yml`) runs lint, the tests, a check that `driver.flow.compose.json` is up to date and `homey app validate --level publish` on every push and pull request.
