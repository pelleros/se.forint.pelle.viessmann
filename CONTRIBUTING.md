# Contributing

Thank you for helping out! This app is a hobby project used by several hundred Viessmann owners, so the most important thing is that an update never breaks what already works for them. The ground rules below exist because each of them has cost something before.

How the app is built is described in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Setup and commands are in the [README](README.md#development).

## Ground rules

1. **No breaking changes for existing users.** These are frozen once released: capability IDs, Flow card IDs, Flow card argument names, types and dropdown values, trigger tokens, the device `data.id`, store keys and the device class. Renaming or removing a capability deletes the user's Insights history and breaks their Flows; it happened once, in v1.0.11. The registry test (`drivers/vicare/__tests__/registry.json`) fails if anything released disappears. Adding is fine; retiring something is the maintainer's decision and gets a `retired` entry with the reason. Never reuse a retired ID.
2. **Capabilities are only ever added automatically, never removed.** When the stored feature list is refreshed, merge the old and the new list; never replace it. A sensor that happens to report `notConnected` at the moment of an upgrade must not lose its capability.
3. **Never commit real API dumps.** Feature and installation dumps contain serial numbers, installation IDs and sometimes addresses. Keep them in the local, ignored `documentation/` folder and turn them into test fixtures with `scripts/anonymizeDump.js` (see [test/fixtures/README.md](test/fixtures/README.md)). `test/fixtures.privacy.test.js` must pass.
4. **English everywhere in the repository:** code, comments, test names, documentation, commit messages and pull requests. User-facing texts are localized (English, German, Dutch, French, Swedish).
5. **Don't edit generated files by hand.** `app.json` is generated by the Homey CLI from `.homeycompose/` and the driver compose files. `drivers/vicare/driver.flow.compose.json` is currently generated from `drivers/vicare/flowCards.js` and `locales/` with `npm run generate`; CI fails if it is out of date.
6. **Use the live Viessmann datapoint list and avoid deprecated datapoints.** Viessmann marks datapoints `deprecated` with a removal date: <https://api.viessmann-climatesolutions.com/documentation/data-points>. Read command limits (`params.*.constraints`, `isExecutable`) from the API at runtime instead of hard-coding them. Check what a datapoint means before mapping it: some values that look like measurements are settings.
7. **Handle every promise.** Await or `.catch()` every SDK call such as `setAvailable`, `setUnavailable` and `setCapabilityValue`. Unhandled rejections are reported as crashes and can stop the app.
8. **Keep the API quota in mind.** Viessmann's free plan allows about 1,450 calls per day per user, and the app polls every two minutes per device. New features must not add calls per poll.

## Reporting a bug

- What you expected and what happened, with your Homey version, app version and Viessmann model.
- If you can, send a diagnostic report from Homey (the app's page > *Send diagnostic report*) with a short message, and mention it in the issue.
- A features dump from the app settings (*Troubleshooting*) helps a lot. It is partly anonymized, but it can still contain serial numbers: remove them before posting it publicly.

## Pull requests

- For anything larger than a small fix, open an issue first so we can agree on the approach.
- One topic per pull request. Behavioural changes need tests; the anonymized fixtures in `test/fixtures/` make that possible without a real installation.
- Before pushing: `npm ci --ignore-scripts`, `npm test`, `npm run lint` and `npm run homey:validate`. CI runs the same checks.
- Please allow edits by maintainers. Small fixes may then be added to your branch as separate commits on top of yours, so your commits stay yours. If your work is used in another way, you are credited with a `Co-authored-by` trailer and in the changelog.
- Releases go to the Homey test channel first, so expect some time between merge and the App Store.

## Code of conduct

Be kind and assume good intent. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
